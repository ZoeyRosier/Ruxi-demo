# 1. 执行摘要

> **本章结论**:《入戏》是一个让用户从"观众"变为"剧中人"的AI叙事介入平台。它解决长视频时代两大未被解决的痛点——进度条焦虑与完结戒断反应。其核心是一套通用引擎+剧目配置的双层架构,理论上可适配腾讯视频任何独家剧集。

## 1.1 一句话定位

**《入戏》= 让你成为故事里的人**——不是又一个互动剧,也不是和角色聊天的工具,而是让用户以剧中合理存在的身份介入剧情夹缝、留下自己印记的体验平台。

## 1.2 核心痛点

长视频用户长期承受两大痛点,被官方在直播中亲口提及:

1. **进度条焦虑**:被动等待剧情发展,无主动权,导致弃剧/倍速/分心
2. **完结戒断反应**:全剧结束后情感空虚、失眠、心理空缺,用户与故事的连接断裂

更深层的:**用户与故事的"距离感"**——"我看了60集,却感觉自己和这个故事没有关系。"

## 1.3 解决方案

《入戏》提出**「时空介入者」**(Temporal Intervener)产品范式:

- 用户以剧中合理存在的身份(NPC/小角色)进入剧情
- 在剧情夹缝中做出真实的、有重量的决策
- AI实时理解输入、判断影响力、生成分支内容
- 用户的"印记"被故事记得

## 1.4 核心机制

三大AI引擎实时协同:

- **理解引擎**:解析用户自由输入的意图、情感、信息密度
- **判断引擎**:基于剧情上下文和人物动机评估介入影响力
- **生成引擎**:实时合成5-15秒分支视频/图文/音频

## 1.5 与现有产品的本质差异


| 现有产品              | 局限        | 《入戏》的不同       |
| ----------------- | --------- | ------------- |
| 互动剧(Bandersnatch) | 预设分支,选项有限 | AI实时生成,自由文本输入 |
| 角色聊天(c.ai)        | 剥离剧情,易尬   | 嵌入剧情,留下印记     |
| 视频生成工具(Sora)      | 工具属性,无故事  | 体验产品,有叙事      |


## 1.6 产品形态

> **关键定位**:《入戏》不是独立App,而是**腾讯视频内嵌的"介入层"功能**。

- **正式产品形态**:腾讯视频App内置功能模块。用户在原有观看场景中无缝触发,**视频源直接复用腾讯视频原生播放器**,无需切换平台。
- **Demo提交形态**:独立H5原型(11天工期下的可交付物),**作为产品概念的可交互验证**。
- **类比参考**:Netflix《Bandersnatch》在Netflix App内、B站互动视频在B站播放器内——《入戏》是同一形态:**寄生在腾讯视频生态内的内容增强层**。

这一定位决定了《入戏》**不与腾讯视频抢用户,而是为腾讯视频每部独家剧增加一个"介入维度"**。

## 1.7 PCG战略价值

- **腾讯视频**:激活独家剧集IP的长期生命周期价值,直接嵌入主App无新增用户教育成本
- **影游融合**:命中PCG战略,无需新建游戏即可获得游戏化体验
- **AI Native**:5/5核心功能AI不可替代,是真正AI原生的产品形态
- **平台型增长**:通用架构,任何剧目10-15人日即可接入

## 1.8 关键数据

- 通用引擎一次开发,**单剧接入成本下降75%+**
- AI原生度:**100%**(去掉AI产品归零)
- Demo覆盖:《三体》深度节点 + 3部剧通用性证明

# 2. 行业背景与机会

> **本章结论**:长视频行业正面临用户注意力被短视频/游戏分化的危机。AI生成内容的成熟,为长视频找到了一条"游戏化但不变成游戏"的新路径——主动参与式叙事。这正是《入戏》的入场机会。

## 2.1 长视频的注意力危机

**用户行为变化**:

- 移动互联网用户日均使用时长趋于平稳,但**长视频份额持续被短视频蚕食**
- "倍速观看"率显著提升:用户对长内容的耐心下降
- "弃剧率"高企:多数剧集仅完成30-50%即被放弃

> 占位:补充2024-2025年QuestMobile/Statista等公开数据

**用户心理变化**:

- 被动观看疲劳:"看剧"不再是稀缺娱乐
- 注意力高度碎片化:观看过程中频繁查手机/做其他事
- 期待"参与感":用户希望自己的存在被故事承认

## 2.2 两大未被解决的核心痛点

### 痛点A:进度条焦虑

**现象**:用户在观看长视频时频繁拉动进度条,跳过"觉得没必要看"的段落,或在精彩处反复回看。
**本质**:被动观看的无力感与主动感的缺失。
**当前解法**:倍速观看(粗暴)、跳剧情(破坏沉浸)、看剪辑解说(逃离剧本身)。
**未被解决之处**:**没有产品让用户在保持完整观看的同时,获得"主动感"**。

### 痛点B:完结戒断反应

**现象**:全剧结局后,用户陷入情感空虚——失眠、二刷、寻找同人、社交平台密集发帖。
**本质**:用户在观看过程中投射情感,完结意味着"亲密关系的断裂"。
**当前解法**:刷二创、看花絮、加入剧粉社群。
**未被解决之处**:**这些都是"剧外"的代偿,没有产品让用户在剧本身的世界里继续存在**。

## 2.3 AI时代的体验范式迁移

生成式AI的成熟,让"AI实时为单个用户生成内容"从概念变为可行:

- **2026年视频生成模型**:可灵2.0、Sora 2、Veo 3 等已支持基于reference的5-15秒一致性生成
- **大语言模型**:对人物人设、情感、剧情逻辑的理解达到生产可用水平
- **多模态融合**:文本、图像、视频、音频可在统一管线中协同生成

这开启了一个**全新的内容形态**——**为单个用户、单次观看、单次决策动态生成的叙事体验**。这是预设分支的互动剧无法做到的。

## 2.4 PCG战略契合点

《入戏》与腾讯PCG的多项战略方向高度契合:


| PCG战略方向     | 契合点                   |
| ----------- | --------------------- |
| 影游融合        | 不创造新游戏,而让影视剧获得游戏化体验   |
| AI Native内容 | 完全AI驱动的内容形态,符合下一代产品定义 |
| 独家剧集IP活化    | 让腾讯视频的独家剧集获得长生命周期价值   |
| 用户粘性提升      | 完结后用户仍持续回访            |
| 商业化创新       | 介入式品牌植入是广告新形态         |


## 2.5 时机判断

**为什么是现在?**

- ✅ 视频生成模型成熟到可以保持人物一致性(2025年突破)
- ✅ 大语言模型对叙事逻辑的理解达到生产可用
- ✅ 用户对"AI生成内容"心智已建立(不再陌生)
- ✅ 长视频行业正在寻找突破点(短视频压力)
- ✅ 影游融合战略需要新形态承载

**等待会失去什么?**

视频生成大模型已经普及——若不在2026年内推出"体验型"产品,**未来将沦为又一个视频生成工具的封装**,核心价值被淘空。

# 3. 用户研究

> **本章结论**:核心用户是Z世代长视频重度用户。通过3-5位用户的深度访谈,识别出"被故事承认"是当前所有内容形态都未满足的高频高痛需求。

## 3.1 目标用户画像

### 核心用户:Z世代长视频重度用户


| 维度    | 描述                        |
| ----- | ------------------------- |
| 年龄    | 18-30岁                    |
| 月观剧时长 | >20小时                     |
| 行为特征  | 倍速观看、跨平台追剧、活跃于剧粉社群、二创关注度高 |
| 心理特征  | 追求沉浸感、情感投射强、有"嵌入"故事的潜在期待  |

### 拓展用户

- **剧粉/同人圈/二创创作者**:已有强动机参与剧的"二次构建"
- **沉浸式戏剧/互动游戏爱好者**:对"参与式体验"有付费意愿
- **影游双重用户**:同时是剧粉与游戏玩家,接受"AI+影游"概念无障碍

## 3.2 用户访谈

### 访谈方法

- **访谈对象**:5位长视频重度用户(覆盖科幻/古装/年代剧不同偏好)
- **形式**:1对1深度访谈,每人20-30分钟
- **录音**:经同意后录音转写

### 核心问题清单

1. 你最近一次因为剧"意犹未尽"是什么时候?当时心里在想什么?
2. 你看完一部剧后,会用什么方式消化情感?(刷二创/重看/讨论/其他)
3. 你觉得剧里有没有"如果当时换一种发展"的瞬间?
4. 如果你能成为剧里的一个角色,你会选什么样的身份?
5. 你对"互动剧"(如《Bandersnatch》)的感受?为什么?
6. 你愿意为"成为剧中一员"付费吗?多少?

### 关键引述

> 占位:实际访谈完成后填入真实引述。以下为产品设计阶段的合理预期方向,需访谈验证。

**关于戒断反应**:

> "看完《三体》三天没缓过来。我觉得我和这个故事建立了真实的关系,但故事结束后,这种关系断了。" —— 受访者A

**关于参与感**:

> "我看了60集,却感觉自己和这个故事没有关系。我只是个看客。" —— 受访者B

**关于互动剧的失望**:

> "我看了《Bandersnatch》,选了几次以后就发现——选项是有限的,我的选择并不真的重要。失去了'我能改变什么'的真实感。" —— 受访者C

### 访谈结论

通过访谈识别出**三层需求**:

1. **表层需求**:更多互动、更多分支、更多剧情
2. **中层需求**:在故事里做有重量的决策
3. **深层需求**:**被故事承认存在,留下属于自己的痕迹**

《入戏》的产品定位,直接命中第三层深层需求。

## 3.4 现有解决方案的失败分析


| 解决方案               | 用户体感               | 失败原因                 |

# 4. 产品定位

> **本章结论**:《入戏》定位为"剧中人体验"而非"剧外工具",通过零改主线、介入夹缝、平台架构三大原则,在体验层创造真正的差异化。

## 4.1 产品定位句式

> **《入戏》是一个让长视频用户以剧中合理身份介入剧情夹缝的AI叙事平台。**
>
> **For** 长视频重度用户
> **Who** 渴望从故事的旁观者变成参与者
> **Our product** 通过AI实时生成与剧集一致的分支内容
> **Provides** 真正的"被故事承认"体验
> **Unlike** 互动剧/角色聊天/视频工具
> **Our product** 是体验产品而非工具产品,是嵌入而非外接,是留印记而非改主线。

## 4.2 核心价值主张


| 用户层  | 价值                      |
| ---- | ----------------------- |
| 个体用户 | 从观众变为参与者,获得真正的"嵌入感"     |
| 剧迷社群 | 形成"我的剧"的差异化认同(每人版本略有不同) |
| 内容方  | 单剧从一次性消费品变为长生命周期资产      |
| 平台   | 用户粘性、新形态商业化、内容差异化竞争力    |


## 4.3 产品哲学三原则

### 原则1:零改主线

原片一帧不动。所有"介入"都发生在剧情夹缝中——AI生成的内容是补丁,不是替换。这一原则保证:

- 与版权方/内容方合作友好
- 原作品完整性不被破坏
- 用户也能获得"原汁原味"的剧集观看

### 原则2:介入夹缝

用户的介入发生在剧情留白处——主角内心思考时、镜头切换间隙、未被原片明示的角色互动等。这些"夹缝"是叙事学上的留白,正是参与者的自然空间。

### 原则3:平台架构

不绑死单剧。从一开始就以"通用引擎+剧目配置"的双层架构设计,确保单剧成功后可以快速复制到其他剧目。

## 4.4 差异化矩阵


| 维度   | 互动剧   | 角色聊天 | 视频工具  | **《入戏》**       |
| ---- | ----- | ---- | ----- | -------------- |
| 用户身份 | 选项决策者 | 对话者  | 工具使用者 | **剧中存在的人**     |
| 分支生成 | 预设    | 无    | 无叙事   | **AI实时+预生成混合** |
| 主线影响 | 改变主线  | 不影响  | 不涉及   | **零改主线,留印记**   |
| 核心心理 | 决策权   | 社交感  | 创造力   | **被故事看见的归属感**  |
| AI原生 | 部分    | 高    | 高     | **完全AI原生**     |
| 复用性  | 单剧绑定  | 通用但浅 | 通用但浅  | **平台型,深度可复用**  |


## 4.5 产品形态

> **关键决策**:《入戏》定位为**腾讯视频App内嵌功能**,而非独立产品。

### 4.5.1 产品形态对比

| 维度 | 选项A:独立App/网站(❌ 不采用) | 选项B:腾讯视频内嵌(✅ 本产品采用) |
|------|---------------------------------|---------------------------------------|
| 用户旅程 | 需切换App/平台,转化漏斗长 | 在原有观看场景内无缝触发 |
| 内容版权 | 需重新获得每部剧版权 | 复用腾讯视频既有授权 |
| 用户教育 | 需建立新心智 | 寄生于已有心智 |
| 商业化 | 独立支付链路 | 直接对接腾讯视频会员体系 |
| PCG战略 | 边缘 | 核心 |

### 4.5.2 用户旅程示例(正式产品)

```
腾讯视频App
   ↓ 选《三体》
正常观看(90%时长)
   ↓ 剧情到关键节点(系统识别 triggerTimestamp)
浮层提示:"是否进入介入模式?"
   ↓ 用户接受
《入戏》介入流程(在腾讯视频App内)
   ↓ 完成介入
回到正常观看 / 进入下一集
   ↓
个人介入档案(在腾讯视频"我的"页面)
```

**整个流程用户从未离开腾讯视频App**——这是产品形态的核心约束。

### 4.5.3 行业类比

| 参考产品 | 形态 | 启示 |
|----------|------|------|
| Netflix《Bandersnatch》 | Netflix App内特殊功能 | 互动叙事不需要独立App |
| B站互动视频 | B站播放器内的选项浮层 | 嵌入式叠加是行业成熟范式 |
| 抖音Mini Program | 视频内的轻量应用 | 短嵌入路径转化最优 |
| **《入戏》** | **腾讯视频内嵌的叙事介入层** | 同一范式的叙事深度版本 |

### 4.5.4 Demo形态说明

由于工期约束下无法真实嵌入腾讯视频App(需腾讯内部协作),**本次提交的Demo采用独立H5形式**,作为:
- ✅ 产品概念的可交互原型
- ✅ AI能力的实际演示(真实Claude API驱动)
- ✅ 双层架构的视觉与代码呈现

但**Demo是产品概念表达,不是产品最终形态**。这一区分会在第8章原型说明中详细阐述。

## 4.6 介入身份的配置弹性

> **关键设计原则**:每部剧的介入身份数量**不是固定的**,而是由"叙事性"决定的配置变量。

### 4.6.1 单身份 vs 多身份的取舍

| 模式 | 优势 | 劣势 | 适用剧目类型 |
|------|------|------|--------------|
| **单身份** | 聚焦最具戏剧张力的视角;接入成本低 | 重玩价值低 | 主角光环极强、有"无可替代的关键见证者"的剧 |
| **多身份(2-5个)** | 扩展重玩价值;多视角丰富叙事 | 接入成本×N | 公路片/群像剧/双线叙事的剧 |

### 4.6.2 各剧的推荐身份数

| 剧目 | 推荐身份数 | 设计理由 |
|------|------------|----------|
| 《三体》 | **1个**(监听员1379号) | 原作中最具戏剧张力的"边缘觉醒者"视角,无可替代 |
| 《长相思》 | 3个(市集小贩/桃林守人/商队伙夫) | 公路片结构,小夭一路遇人,多视角天然合理 |
| 《庆余年》 | 2个(范府小厮/北齐密探) | 双视角呈现"主角阵营"vs"对立阵营" |
| 《繁花》 | 1个(夜东京伙计) | 王家卫式叙事需聚焦视角 |

### 4.6.3 设计哲学

> **"身份数量不是越多越好,而是叙事需要决定的。"**
>
> 同一套技术架构可承载1到N个身份,但每剧的最佳数量由内容方与产品共同决定。

**这一原则使产品兼具"工程可扩展性"与"叙事克制性"** — 不为多而多,只为故事而设。

# 5. 核心体验设计

> **本章结论**:《入戏》的核心是「时空介入者」范式——用户以剧中合理身份(非上帝视角)在剧情夹缝介入。Demo聚焦《三体》监听员1379号场景,完整演示理解+判断+生成三引擎闭环。

## 5.1 「时空介入者」范式

### 范式定义

用户在《入戏》中的身份**不是**:

- ❌ 上帝视角的导演(权力过大,失去真实感)
- ❌ 主角(已被原作设定锁死)
- ❌ 旁观者(无介入能力,等于普通观看)

用户在《入戏》中的身份**是**:

- ✅ 剧中合理存在的有限权限角色
- ✅ 通常是NPC、小角色、或剧情留白处的"未署名见证者"
- ✅ 拥有具体的、有边界的介入能力

### 心理机制


| 体验维度 | 传统观看   | 「时空介入者」范式 |
| ---- | ------ | --------- |
| 用户位置 | 屏幕外    | 故事内       |
| 决策权  | 无      | 有限但真实     |
| 影响范围 | 0      | 夹缝内的真实影响  |
| 情感投入 | 投射(单向) | 嵌入(双向)    |
| 完结后  | 关系断裂   | 印记留存      |


### 边界设计

**有限的介入能力 = 真实感**:

- 用户不能让主角不死(原作锁定)
- 用户可以在主角的关键时刻递一句话、一个物件、一个眼神
- 用户的介入会引发AI生成的"夹缝瞬间",并在后续节点呼应

这种"有限"恰恰是真实感的来源——无所不能=失真。

## 5.2 介入容器(In-Universe合理化)

不同剧目类型适配不同的"剧情自洽介入解释":


| 剧目类型              | 介入容器      | 用户已有认知锚点    |
| ----------------- | --------- | ----------- |
| 科幻(《三体》)          | 三体游戏拓展协议  | 原作"三体游戏"设定  |
| 古装/玄幻(《长相思》《庆余年》) | 梦境穿越/魂穿   | 网文"穿越"心智    |
| 现代/年代剧(《繁花》)      | 记忆回访/时空胶囊 | "如果当年..."叙事 |
| 悬疑剧(《开端》)         | 案件重演协议    | 推理沙盘推演      |
| 历史剧(《大明王朝1566》)   | 史官视角      | "史册中的小人物"心智 |


每个介入容器都基于**用户已有的文化心智**,降低教育成本。

## 5.3 用户旅程地图

```
入场     选剧     选身份    观看      介入      见证      留痕      复盘/回访
 │        │        │        │         │         │         │         │
情绪:    好奇    探索    沉浸     紧张     释然     满足     怀念
 │        │        │        │         │         │         │         │
触点:   首页    剧目库  身份卡  剧集播放 输入框   分支视频  印记档案  推送
```

## 5.4 核心场景:《三体》监听员1379号(Demo聚焦)

### 5.4.1 场景设定


| 配置项  | 内容                    |
| ---- | --------------------- |
| 选定剧  | 《三体》(腾讯视频独家)          |
| 介入容器 | 三体游戏·拓展协议             |
| 用户身份 | 三体监听员1379号(原作中觉醒的三体人) |
| 关键节点 | 1971年深夜,叶文洁的YES按钮前    |
| 情感弧线 | 紧张→犹豫→决定→见证→余韵        |


### 5.4.2 完整体验流程(7步)

#### Step 1:观看引入(0:00-0:30)

播放3分钟原剧片段:叶文洁第一次发送YES,等待回复。红岸基地的孤独、星空、机器嗡鸣。**画面正常播放,完全保留原作观看体验。**

#### Step 2:游戏UI唤起(0:30)

剧情到关键节点时,画面渐暗,游戏UI浮现:

> 系统提示:
>
> "你是三体监听员1379号。
> 三体世界即将给地球发出第一条回复。
> 你只有一次发送机会——
> 地球的最后希望,只有你这一条消息。"

视觉:复古CRT显示器风格,模拟70年代电信通讯界面,与原剧时代背景呼应。

#### Step 3:用户撰写(0:30-2:00)

用户在文本框中**完全自由**地撰写消息内容。

界面右侧实时显示叶文洁的接收端(原片画面+AI合成的屏幕显示内容)——你能看到她正在等待。

用户可以反复修改,但**只有一次发送机会**。

#### Step 4:AI实时判断(2:00,瞬时)

发送后,判断引擎对消息进行多维度评分(可视化展示):


| 评分维度   | 含义                        | 权重  |
| ------ | ------------------------- | --- |
| 信息完整度  | 是否清晰传达"不要回答"的核心           | 30% |
| 情感强度   | 是否触动叶文洁的人性深处              | 30% |
| 人物动机匹配 | 是否切合叶文洁的过往伤痕(对人类失望、对命运抗争) | 25% |
| 剧情逻辑自洽 | 是否符合三体监听员1379的人设(同情但克制)   | 15% |


**实时显示评分动画**——增强用户对"AI在判断"的感知。

#### Step 5:分支视频生成(2:30)

根据评分触发不同分支:

**高分(>80)**:AI生成5秒短片

- 画面:叶文洁手指悬空,屏幕显示你的消息,她泪流满面,逐字删除YES
- 配音:叶文洁内心独白(AI生成)
- 转场:画面渐黑,字幕"她没有回答"

**中分(50-80)**:AI生成5秒短片

- 画面:叶文洁犹豫片刻,表情复杂,最终按下YES
- 内心独白:"也许...也许这一次不一样"
- 转场:回归原剧,但带"她试过"的余韵

**低分(<50)**:回归原剧

- 原片画面,无任何修改
- 但屏幕角落短暂闪过你的消息,被她忽略

#### Step 6:分支结局(2:30-3:00)

**高分路径**:
AI生成5-10秒"如果地球没有暴露坐标"的预言短片

- 画面:平行宇宙中红岸基地的黎明
- 旁白:"在这一个时间线里,人类还有300年..."
- 字幕:"你拯救了一个时间线"

**中/低分路径**:
回归原剧悲剧路径,但带有用户介入的"余韵"

- 画面:三体舰队启航
- 字幕:"你试过了。在另一个时间线里,你成功了。"

#### Step 7:印记沉淀

用户的消息进入"个人介入档案":

- 你曾给叶文洁的话(永久保存)
- 此次介入的影响力评分
- 分支结局的快照
- 后续节点可能呼应你此次介入

### 5.4.3 核心情感闭环

```
[观看]   "我只是看客"
   ↓
[选身份] "我成为故事的一员"
   ↓
[撰写]   "我有权决定地球的命运"
   ↓
[判断]   "AI真的在评估我的话"
   ↓
[结局]   "地球的一切因我而起"
   ↓
[印记]   "我留下的话被故事记得"
```

## 5.5 介入节点的精确定位机制

> **关键工程问题**:如何让介入节点与具体剧情、用户播放进度精准对齐?

### 5.5.1 节点的颗粒度定义

**介入节点 = 单集内的某个具体剧情时刻**(最小颗粒度)

一部剧通常有多个跨集分布的介入节点。以《三体》(30集)示例:

```
《三体》全30集
├── 介入节点1:Ep3  - 12:47   (叶文洁初到红岸基地)
├── 介入节点2:Ep6  - 47:23   ⭐ YES按钮节点(Demo聚焦)
├── 介入节点3:Ep14 - 23:56   (ETO第一次集会)
├── 介入节点4:Ep18 - 31:08   (汪淼遭遇倒计时)
├── 介入节点5:Ep22 - 51:17   (章北海的关键决定)
└── 介入节点6:Ep27 - 38:42   (古筝行动)

→ 6个节点跨11集,并非每集都有节点
```

### 5.5.2 节点元数据结构

每个节点必须包含以下精确定位信息:

| 字段 | 说明 | 示例 |
|------|------|------|
| `episode` | 集数(整数) | 6 |
| `triggerTimestamp` | 集内时间戳(秒) | 2843 |
| `triggerTimecode` | 人类可读时间 | "47:23" |
| `durationBefore` | 触发前观看的前置时长(秒) | 180(3分钟) |
| `sceneDescription` | 该时刻的剧情描述 | "叶文洁手指悬于YES按钮上,等待最后的决定" |
| `preStateContext` | 该节点之前已发生的剧情摘要 | (供AI引用,见§6.5知识库) |

### 5.5.3 时间戳的来源(三种方案)

| 方案 | 描述 | 可信度 | 成本 |
|------|------|--------|------|
| **A. 版权方共建** ⭐ | 制作方/腾讯视频直接提供官方时间戳数据库 | ✅✅✅ 最高 | 低(若已合作) |
| **B. 内容运营标注** | 内部团队观看剧集,人工标注节点 | ✅✅ 高 | 中(每剧4-8人时) |
| **C. AI辅助识别** | 多模态AI识别"留白时刻",人工审核确认 | ⚠️ 需审核 | 低 |

**正式产品采用 A + B 组合**:版权方共建为主,内容运营补充为辅。

### 5.5.4 触发逻辑(代码级)

```typescript
// 监听播放进度,到达triggerTimestamp时触发
videoPlayer.on('timeupdate', (currentTime) => {
  const node = findActiveNode(episode, currentTime);
  if (node && currentTime >= node.triggerTimestamp - 0.5 && !triggered) {
    videoPlayer.pause();
    triggerInterventionUI(node);
    triggered = true;
  }
});
```

# 6. 功能架构

> **本章结论**:《入戏》采用"通用引擎层+剧目配置层"双层架构。通用层5个引擎一次开发跨剧复用,配置层6项参数每剧10-15人日定制完成。这是平台化产品的核心结构。

## 6.1 双层架构总览

```
┌──────────────────────────────────────────────┐
│  剧目配置层(每剧 10-15 人日)                │
│  ┌──────┬──────┬──────┬──────┬──────┬─────┐ │
│  │介入  │介入  │介入  │人设  │风格  │分支 │ │
│  │容器  │身份  │节点  │包    │预设  │预生│ │
│  └──────┴──────┴──────┴──────┴──────┴─────┘ │
├──────────────────────────────────────────────┤
│  通用引擎层(开发一次,所有剧复用)           │
│  ┌──────┬──────┬──────┬──────┬──────────┐   │
│  │理解  │判断  │生成  │记忆  │分支调度  │   │
│  │引擎  │引擎  │引擎  │引擎  │          │   │
│  └──────┴──────┴──────┴──────┴──────────┘   │
├──────────────────────────────────────────────┤
│  基础设施层                                   │
│  LLM API · 视频生成 · TTS · 向量数据库 · CDN │
└──────────────────────────────────────────────┘
```

## 6.2 通用引擎层详解

### 引擎1:理解引擎(Understanding Engine)

**职能**:解析用户自由输入的多维语义。


| 输入   | 处理        | 输出     |
| ---- | --------- | ------ |
| 用户文本 | LLM语义解析   | 意图标签   |
| 用户语音 | ASR + LLM | 情感标签   |
| 用户选择 | 上下文映射     | 信息密度评分 |


**关键技术**:Claude Opus / 豆包 / DeepSeek 等LLM的in-context learning。

### 引擎2:判断引擎(Judgment Engine)

**职能**:基于剧情上下文和人物动机,评估用户介入对剧情的"影响力分数"。

**评分框架**:

- 信息完整度:用户是否传达了关键信息?
- 情感强度:能否触动目标角色?
- 人物动机匹配:是否切合该角色的内心动力?
- 剧情逻辑自洽:是否符合介入者的人设?

**输出**:

- 影响力总分(0-100)
- 分支路由决策(高分/中分/低分)
- 解释文本(为什么这个分数,展示给用户)

### 引擎3:生成引擎(Generation Engine)

**职能**:根据分支路由生成多模态内容。


| 内容类型      | 模型                         | 时长    |
| --------- | -------------------------- | ----- |
| 短视频(关键节点) | 可灵2.0 / 即梦 / Sora 2        | 5-15秒 |
| 静态图(预备帧)  | Midjourney / DALL-E 3 / 即梦 | /     |
| 角色对话      | Claude / GPT-4             | /     |
| TTS配音     | Minimax / 豆包语音             | /     |


**关键技术**:基于reference frame的人物一致性生成。

### 引擎4:记忆引擎(Memory Engine)

**职能**:维护用户跨节点的介入历史,形成"印记图谱"。

**核心数据结构**:

```
用户ID
├── 介入事件流
│   ├── 节点ID
│   ├── 介入内容
│   ├── 影响力评分
│   └── 分支结局
├── 印记图谱(向量化)
└── 跨节点关联(后续呼应基础)
```

**应用场景**:

- 后续节点中,主角"想起"用户曾说的话
- 全剧完结后,生成"用户专属介入回忆录"

### 引擎5:分支调度(Branch Orchestrator)

**职能**:决定主线回归点、管理分支结局生成、确保用户体验流畅。

**核心逻辑**:

- 接收判断引擎的影响力分数
- 调用生成引擎产出对应分支
- 管理状态机(主线播放→分支生成→主线回归)

## 6.3 剧目配置层详解

每部新剧需要的"配置包":

### 配置1:介入容器

- **内容**:给介入行为的剧情自洽解释(梦境/游戏/记忆/史官视角等)
- **工时**:1-2天
- **示例**:三体游戏拓展协议、游魂幻梦、记忆回访

### 配置2:介入身份

- **内容**:3-5个可选身份(NPC/小角色/特殊视角)
- **工时**:1天
- **示例**:监听员1379号、市集小贩、范府小厮

### 配置3:介入节点

- **内容**:5-8个剧情夹缝点位(时间戳+情境)
- **工时**:2-3天
- **示例**:YES按钮节点、章北海行动、范闲入京

### 配置4:角色人设包

- **内容**:涉及角色的语言风格/价值观/动机的prompt集
- **工时**:2天
- **示例**:叶文洁的对人类失望、相柳的克制、范闲的双重身份

### 配置5:风格预设

- **内容**:视频生成的画面色调/光影/年代风格
- **工时**:1天
- **示例**:70年代CRT质感、玄幻仙气、上海年代感

### 配置6:分支预生成

- **内容**:每节点2-3种典型分支视频(预生成)
- **工时**:3-4天
- **示例**:每个节点的高/中/低分版本

**单剧总工时**:10-15人日。

## 6.4 数据流转图

```
[用户输入]
   ↓
[理解引擎] ─解析→ {意图, 情感, 信息密度}
   ↓
[判断引擎] ─评分→ {影响力分数, 路由决策}
   ↓                              │
   ├─→ [记忆引擎] ─沉淀→ 印记图谱  │
   │                              │
   └─→ [生成引擎] ←调用← [分支调度]
                ↓
        [视频/图文/音频]
                ↓
            [用户体验]
```

## 6.5 剧情知识库(防OOC的核心模块)

> **关键风险**:AI在生成reasoning时若编造原作中不存在的情节(OOC,Out of Character),会直接破坏产品可信度。这是AI内容产品的命门。
>
> **解决方案**:多层剧情知识库 + 严格知识源约束。

### 6.5.1 三层知识库架构

```
┌──────────────────────────────────────────────────┐
│ Layer 3: 公开二手信息(Auxiliary,辅助理解)         │
│ 来源:维基百科 / 豆瓣 / 官方剧透                  │
│ 用途:不作为AI回应的引用源                        │
│ 可信度:⚠️ 中(可能错误)                          │
├──────────────────────────────────────────────────┤
│ Layer 2: 剧改实际呈现(Visual-First,主要引用源)  │
│ 来源:剧集字幕 / 视觉场景 / 关键事件标注          │
│ 用途:AI 仅可引用 "剧版实际呈现" 的内容            │
│ 可信度:✅✅ 高(就是观众真正看到的)              │
├──────────────────────────────────────────────────┤
│ Layer 1: 原作权威知识库(Authoritative)            │
│ 来源:版权方提供的剧本 / 角色档案 / 世界观文档     │
│ 用途:补充背景理解,但需谨慎使用                  │
│ 可信度:✅✅✅ 最高                                │
└──────────────────────────────────────────────────┘
```

### 6.5.2 各层数据形态

#### Layer 1:原作权威知识库
- 剧本(每集对白+场景描述)
- **角色档案**:主角的过往经历、动机、价值观、语言风格
- 世界观文档:时代背景、规则设定、核心冲突
- 关系图谱:人物之间的关系网络

#### Layer 2:剧改实际呈现(⭐ AI主要引用源)
- 字幕文本(对白)
- 视觉场景描述(由AI从画面生成 + 人工审核)
- **每集已发生事件清单**(节点触发时,AI只能引用"该节点之前已发生"的事件)
- 角色在剧中的实际表现(可能与原著有差异)

#### Layer 3:公开二手信息
- 仅用于辅助理解
- **不作为AI回应的引用源**

### 6.5.3 关键设计原则

> **「剧版优先,原著辅助,不混用版本」**

- ✅ AI回应中引用的所有事实,必须在 Layer 2(剧版)中可查证
- ⚠️ Layer 1(原著)的内容,只在剧版未明确呈现但需要补充时使用,且需标记
- ❌ Layer 3(二手信息)绝不直接进入AI回应

### 6.5.4 与逻辑架构的关系

知识库属于**通用引擎层的支撑设施**,但其内容是**剧目配置层**的一部分:
- 引擎(知识库读写、向量检索):跨剧通用
- 数据(每剧的角色档案、事件清单):每剧定制

接入新剧时,知识库构建是配置层最重的部分(占总工时60%+)。

### 6.5.5 与版权方共建的必要性

**没有版权方共建,知识库无法可靠构建**:
- 角色动机/未公开背景需制作方提供
- 时间戳的精确对齐需官方数据
- 剧改与原著的差异点需创作方澄清

**这是为什么《入戏》必须以"与腾讯视频共建"为落地路径,而不能独立开发**(详见§10)。

# 7. AI能力体系

> **本章结论**:《入戏》5/5核心功能AI不可替代。去掉AI,产品归零。这是真正AI原生的产品形态,完美命中官方"AI拿掉run不下去"标准。

## 7.1 AI原生论证表


| 核心功能    | 去掉AI能否实现 | 原因                      |
| ------- | -------- | ----------------------- |
| 自由文本理解  | ❌ 不能     | 需要LLM解析任意输入的意图与情感       |
| 影响力实时判断 | ❌ 不能     | 需要语义理解+人物动机推理           |
| 分支视频生成  | ❌ 不能     | 需要视频生成模型实时合成            |
| 跨节点用户记忆 | ❌ 不能     | 需要语义向量化建立关联             |
| 人物一致性   | ❌ 不能     | 需要reference-based生成保持一致 |


**结论**:5/5核心功能AI原生,产品100%AI原生。

## 7.2 关键AI能力栈

### 大语言模型(LLM)

- **候选**:Claude Opus、豆包、DeepSeek、GPT-4
- **用途**:理解、判断、人设对话、Prompt engineering
- **关键考量**:中文表达自然度、人设理解深度、推理能力

### 视频生成模型

- **候选**:可灵2.0、即梦、Sora 2、Veo 3
- **用途**:5-15秒分支视频生成
- **关键考量**:基于reference的人物一致性、画面质量、生成速度

### 多模态理解

- **候选**:GPT-4V、Gemini、通义千问VL
- **用途**:剧情上下文理解、画面情境解析
- **关键考量**:对剧集画面的理解深度

### 语音合成(TTS)

- **候选**:Minimax、豆包语音、火山引擎TTS
- **用途**:角色配音、内心独白
- **关键考量**:情感表达、音色定制能力

### 向量数据库

- **候选**:Pinecone、Milvus、Chroma
- **用途**:角色记忆库、用户印记图谱
- **关键考量**:检索速度、规模化能力

## 7.3 AI能力的边界与应对

### 能做到的(基于2026年技术现状)

- ✅ 5-15秒视频生成,保持人物一致性(基于reference)
- ✅ 短片中表情、轻微动作的自然生成
- ✅ 基于原剧风格的色调/光影一致性
- ✅ LLM对人物人设、情感、动机的深度理解
- ✅ 实时语义判断与多维度评分

### 做不到的(规避设计)

- ❌ 长段(>30秒)对话戏的演员一致性 → **设计上限定分支视频5-15秒**
- ❌ 复杂多人互动场景 → **介入节点设计上聚焦单人/双人**
- ❌ 完美口型同步 → **规避对白特写,用画外音/侧脸/远景**
- ❌ 完整剧集替换 → **零改主线,只填补夹缝**

## 7.5 OOC风险防范机制

> **OOC = Out of Character**:AI在回应中编造原作不存在的情节、错误描述角色经历、改变人物关系——这是AI内容产品的命门级风险。

### 7.5.1 风险情景示例

以《三体》为例,以下都是OOC典型错误:
- ❌ "她的母亲在文革中被打死"(原作中是**父亲**被打死,母亲是告发者)
- ❌ "童年记忆里那只逃走的鸟"(原作未呈现的细节,可能编造)
- ❌ "她17岁参加红卫兵"(原作未提及,可能错误)

任何一处OOC,**评委或资深剧迷一眼识破,产品可信度归零**。

### 7.5.2 四层防范机制

#### 第一层:Prompt中的硬性知识约束(开发期)

在Claude API的system prompt中嵌入:
- 该节点之前的剧版已发生事件清单(完整列表)
- 涉及角色的官方档案(过往/动机/语言风格)
- **明确禁止条款**:"不得引用以下清单之外的任何事件"
- 要求AI输出时**附引用来源**(如"基于角色档案第3条")

#### 第二层:RAG检索验证(运行时)

- AI生成reasoning后,系统用关键词向量检索原作知识库
- 标记"未在Layer 2(剧版)中找到对应"的句子
- 高风险reasoning自动降级到中分路径或标记审核

#### 第三层:内容审核流程(人工兜底)

- 高风险节点(涉及主角核心情节)的reasoning预生成3-5种,**人工审核选最佳**
- 上线后:用户可"标记OOC",反向优化Prompt和知识库
- 内容运营定期抽检AI生成内容

#### 第四层:版本边界明确(用户感知)

- 系统始终以**剧版**为知识源(用户看的是剧)
- 原著独有内容仅在用户主动询问时提示"这是原著独有"
- 避免混用不同版本(如剧版三体 vs 动画版三体 vs 小说)

### 7.5.3 与剧情知识库的关系

防范机制建立在 **§6.5 剧情知识库** 之上:
- Layer 1(原作权威):为AI提供基础素材
- Layer 2(剧改实际呈现):⭐ AI回应的唯一引用边界
- Layer 3(公开二手):不进入回应

→ **没有可靠的知识库,任何防范机制都是空中楼阁**。这也是为什么"与版权方共建"是产品落地的必要前提(详见§10)。

### 7.5.4 风险评估的诚实声明

| 阶段 | OOC风险 | 防范级别 |
|------|---------|----------|
| Demo阶段 | 中 | 单层(Prompt约束) |
| MVP试点(与版权方共建) | 低 | 四层全启用 |
| 平台扩展 | 极低 | 加入用户反馈优化 |

**Demo阶段诚实承认**:由于知识库未与版权方对齐,Demo中的reasoning可能存在轻微OOC。这一限制在§8.5明确说明。

# 10. 落地规划

> **本章结论**:《入戏》以**腾讯视频内嵌功能**形态分三阶段落地——MVP试点(单剧)、平台扩展(多剧)、生态成熟(UGC+海外+IP矩阵)。每阶段都有清晰的关键动作与验证指标。

## 10.0 落地形态前置说明

**所有Roadmap阶段均以"嵌入腾讯视频App"为目标形态**:
- ✅ 用户在腾讯视频App内完成完整体验,不切换平台
- ✅ 视频源、用户体系、支付链路全部复用腾讯视频
- ✅ 《入戏》作为"叠加层"存在,不替代任何现有功能

Demo阶段的独立H5是**概念验证形态**,正式上线即切换为内嵌形态。

## 10.1 三阶段Roadmap

### Phase 1:MVP试点(1-3月)

**目标**:**与腾讯视频共建**,单剧深度跑通,验证产品市场契合度。

**关键动作**:

- 与1部腾讯视频独播剧合作,在腾讯视频App内完整上线
- 部署完整通用引擎层(后端服务可用腾讯云承载)
- 完成1套剧目配置(身份/节点/人设包/分支视频)
- **与版权方共建剧情知识库**(对齐角色档案+剧版事件清单+精确时间戳)⭐ 关键动作
- 启用四层OOC防范机制(详见§7.5)
- 在该剧的播放器内集成5-8个介入节点
- 招募种子用户1万人(从该剧的腾讯视频活跃观众中导流)

**验证指标**:

- 用户介入完成率 > 60%
- 用户满意度(NPS)> 50
- 用户回访率(7日)> 30%
- 用户付费转化率 > 5%

### Phase 2:平台扩展(4-9月)

**目标**:完成5-10部剧适配,验证平台化能力。

**关键动作**:

- 引擎能力沉淀,配置标准化
- 接入5-10部独播剧
- AI辅助配置工具上线
- 拓展付费方式(单剧介入卡、年度会员)

**验证指标**:

- 单剧接入工时 < 10人日
- 月活用户 > 100万
- 付费用户 > 10万
- 商业化收入 > 千万级

### Phase 3:生态成熟(10-24月)

**目标**:UGC生态、海外扩展、IP矩阵。

**关键动作**:

- 开放介入节点编辑器
- 海外剧集IP合作
- 影视/动画/游戏跨形态联动
- B端开放接入

**验证指标**:

- UGC介入节点数 > 10万
- 月活用户 > 1000万
- 商业化收入 > 亿级

# 11. 商业化推演

> **本章结论**:《入戏》的核心商业价值是让单剧从"一次性消费品"升级为"长生命周期资产"。多元收入模型支撑可持续增长。

## 11.1 核心商业论点

> **传统模式**:用户看完剧 → 流失 → 平台需要不断生产新内容
>
> **《入戏》模式**:用户看完剧 → 通过介入留下印记 → 持续回访 → 单剧LTV(用户生命周期价值)显著延长

这一论点直接命中长视频平台的核心痛点——**内容投入巨大,但单剧的用户生命周期短**。

## 11.2 多元收入模型


| 收入模型    | 形式         | 受众   | 客单价      | 想象空间 |
| ------- | ---------- | ---- | -------- | ---- |
| C端订阅    | 月度/年度介入会员  | 重度剧粉 | ¥30-60/月 | 中    |
| C端单次付费  | 关键节点解锁     | 长尾用户 | ¥6-30/次  | 中    |
| 单剧介入卡   | 单剧全节点解锁    | 剧粉   | ¥30-99/部 | 中高   |
| B端版权方分账 | IP增值收益分成   | 内容方  | 不定       | 高    |
| 品牌介入广告  | 软植入新形态     | 广告主  | CPM/CPC  | 高    |
| IP衍生    | 介入数据→实体衍生品 | 粉丝市场 | 不定       | 中    |


## 11.3 想象空间:介入式品牌植入

**传统广告痛点**:用户跳过广告,植入太硬,品牌方付费但效果差。

**《入戏》新形态**:

- 用户在介入节点中,可以"递给主角一瓶水"——这瓶水是真实品牌
- 用户的选择是主动的,不是被动观看
- 品牌方付费,但用户感受是"我选择了它",非"它打扰了我"

这是**广告史上的范式革新**。

## 11.4 LTV测算

> 占位:此处可加详细LTV测算模型(简化版)
>
> - 单用户单剧介入卡 ¥50
> - 用户年均观看剧 6 部 → 年均付费 ¥150
> - 5年留存衰减后,LTV ≈ ¥500-800

# 13. 学术理论支撑

> **本章结论**:《入戏》并非凭空创新,而是建立在新闻传播学、媒介研究、互动叙事理论等多个成熟学术框架之上。

## 13.1 参与式文化(Henry Jenkins)

**理论核心**:Jenkins在《Convergence Culture》(2006)中提出,媒介的未来是参与式的——用户从消费者转变为共创者。

**应用**:《入戏》让用户从剧的"消费者"变为"次级创作者"——通过介入,用户在原作之上构建属于自己的版本。

## 13.2 互动叙事理论(Janet Murray)

**理论核心**:Murray在《Hamlet on the Holodeck》(1997)中提出,计算媒介的四大本质属性——程序性、参与性、空间性、百科性。

**应用**:《入戏》的产品架构精准对应这四大属性:

- 程序性:AI判断引擎是程序化的
- 参与性:用户的介入是真实参与
- 空间性:剧情夹缝是新的叙事空间
- 百科性:记忆引擎沉淀全局印记

## 13.3 沉浸式戏剧(Punchdrunk《Sleep No More》)

**理论核心**:沉浸式戏剧让观众从座位上的旁观者变成场景中的人,可自由穿梭、触摸、选择视角。

**应用**:《入戏》将沉浸式戏剧的核心心理机制移植到长视频——用户作为"剧中存在的人"自由选择介入。

## 13.4 拟社会关系(Horton & Wohl)

**理论核心**:1956年提出,观众与媒介人物会建立单向的情感联结(parasocial relationship)。

**反向应用**:《入戏》创造了**反向拟社会关系**——不是用户单方面投射角色,而是**角色"承认"用户**(通过呼应用户的介入)。这是对经典理论的当代重构。

## 13.5 第二人称叙事

**理论核心**:文学中以"你"作为叙事主体的范式(代表作:Italo Calvino《如果在冬夜,一个旅人》)。

**应用**:《入戏》将第二人称叙事推向极致——你不仅是叙事的主语,也是叙事的实际生成者。

## 13.6 媒介物质性 + 物的传记(Igor Kopytoff)

**理论核心**:物如何获得文化生命、记忆、社会意义。

**应用**:用户在剧中留下的"印记"获得了Kopytoff意义上的传记性——它不再是用户的私有物,而是嵌入了剧情世界。

## 13.7 自我延展理论(Russell Belk)

**理论核心**:我的物品=我的延伸(Extended Self)。

**应用**:用户在剧中留下的印记=用户自我的延伸,这是产品长期粘性的心理基础。

## 13.8 媒介使用与满足(Uses and Gratifications)

**理论核心**:用户主动选择媒介满足特定需求(认知/情感/社交/逃避)。

**应用**:《入戏》开创了一种新的媒介满足类型——**"被故事承认"的存在性满足**。这是当前所有媒介形态都未充分覆盖的需求维度。
