## 1. 阻塞性 bug(必须修)

### Bug 1:Activate 页(UI 唤起瞬间)useEffect 循环

- **现象**:在 Figma Make 里跑 activate 页时,出现 "stuck in a loop" 错误
- **触发条件**:从剧目详情页跳转到 activate 页时
- **可能原因**:
  - useEffect 依赖错误,动画状态在 onComplete 里更新触发动画的 state
  - 主题切换在 render 中直接调用 setState
  - GSAP timeline 没有正确管理生命周期
- **修复方向**:
  - 用 `useRef` 标志位防重复触发
  - 用 CSS keyframes 替代 state-driven 动画
  - `setTheme('santi')` 必须在 `useEffect(() => { ... }, [])` 内调用,不能在 render 中

## 2. 演示性简化(需要改成真实)

### 简化 1:AI 评分页的 Reasoning 是静态预制

- **现象**:无论用户输入什么,AI Reasoning 框中显示的都是固定的一段话:
  > "她的母亲在文革中被打死。你提到了她童年记忆里那只逃走的鸟——这击中了她最深处的犹豫。她的手指在发送键上停留了 4.2 秒。"
- **问题**:任何输入都返回同一段话,完全没有 AI 判断逻辑
- **修复方向**:
  - 在 Cursor 版本中接入真实 Claude API
  - 使用 PRD-cursor.md §8.3 中的判断 Prompt 模板
  - Reasoning 应基于用户实际输入动态生成
  - 评分(0-100)、Branch(high/medium/low)也应是真实计算结果

### 简化 2:介入身份默认只有 1 个

- **现象**:每个剧目只有默认的一个身份(如《三体》→ 监听员1379号),用户无法选择
- **问题**:与 PRD §5.4 设计不符(应该有 3 个身份可选)
- **修复方向**:
  - 在剧目详情页提供 3 个身份选择
  - 三体身份:监听员1379号 / ETO 渗透者 / 红岸基地技术员
  - 不同身份对应的可介入节点不同

### 简化 3:介入节点是针对整部剧还是单集?

- **现象**:原型中的"节点"看起来是抽象的剧情节点,没有明确的"集数 + 时间码"对应
- **问题**:
  - 真实产品中,介入节点应该绑定到具体某一集的具体时间戳
  - 怎么保证节点和剧集进度条对得上号?
- **修复方向**:
  - 数据模型 InterventionNode 中明确包含:`episodeNumber`(第几集) + `triggerTimestamp`(秒)
  - 节点列表 UI 中显示:"《三体》第 3 集 · 23:47"
  - 视频播放页的进度条到 triggerTimestamp 时自动暂停

### 简化 4:剧情上下文/角色人设的 grounding

- **问题**:
  - 系统如何确保 AI 对剧情的理解是正确的?
  - 角色人设、经历、人物关系的真实性如何验证?
  - 如"她的母亲在文革中被打死"——这个情节是否在《三体》原作中存在?(✅ 是真实的)
  - 但其他细节怎么确保不 OOC(out of character)?
- **修复方向**:
  - 每个剧目需要一份「剧情圣经」(Story Bible),记录关键剧情事实
  - 评分 Prompt 中明确引用 Story Bible 的事实
  - Cursor 版本中需要在 themes/santi/ 下建立 story-bible.md 或 grounding.ts
